## Legal pages, consent and data requests

No analytics library loads before a choice: the `sme24_consent` cookie (`granted:<version>` or `denied:<version>`, a stale version counting as no answer) is written only by `setConsent` and `clearConsent` in `src/features/legal/actions.ts`, never by browser code assigning `document.cookie`, and the gate in `src/lib/analytics/client.tsx` is the one place that may call `posthog.init`. Withdrawal clears the `ph_` prefixed storage and cookies itself rather than calling `posthog.reset` or `opt_out_capturing`, because both return early while `__loaded` is false, so a withdrawal after a reload would clear nothing. Every fact on the four static pages under `src/app/[locale]/(marketing)/{privacy,terms,imprint,cookies}/` comes from a constant (`PROCESSORS` and `RETENTION` in `processors.ts`, `SITE`, the dates in `dates.ts`), never from prose, and `docs/legal/record-of-processing.md` is the table by table record a pgTAP test keeps honest. `CURRENT_TERMS_VERSION` in `terms.ts` is compared by equality, never by ordering (the column is `text`, so `'10' < '2'`), and bumping it blocks every signed in user behind a dialog, so it also owes a `legal.terms.changelog.<version>` key in both catalogs and a `TERMS_VERSIONS` entry. `data_requests` carries one open row per person per kind through a partial unique index rather than an application read, `UPDATE` is revoked from every app role so `updateDataRequest` authorises the caller and writes through the service client, and fulfilling a deletion runs `anonymisePerson` before recording the fulfilment, deliberately leaving `orders`, `invoices`, `order_events` and `stripe_events` alone for the ten years Art. 958f CO requires. `DATA_REQUEST_TRANSITIONS` in `schema.ts` is the state machine, because there is no database trigger for it. Strings live in the `legal` namespace in both catalogs; the `data_request.received` alert rides the rail in `docs/email.md`. The bar is fixed to the bottom of the viewport from the root layout, so it covers the signed in areas and the public pages alike: anything anchored to the bottom of either must reserve the height it publishes as `--consent-bar-height` (the signed in sidebar footer in `app-sidebar.tsx` and the marketing wrapper in `(marketing)/layout.tsx` both do), or an opaque bar lands on the focused control and nothing there can be clicked. The per environment checklist (the four pages, zero PostHog requests before a choice, the Slack alert, one real export and one real deletion, the lawyer's pass as feature 26's launch gate) lives in `docs/legal.md`.
