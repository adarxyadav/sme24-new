## Analytics events and monitoring

Every event name is a member of `ANALYTICS_EVENTS` in `src/lib/analytics/events.ts` with a Zod schema beside it in `analyticsProperties` (`catalogue.ts`) under an `as const satisfies Record<AnalyticsEvent, z.ZodType>` check, so a name without a schema fails the typecheck and a free string never reaches `captureServerEvent`; names are `object.verb_past` with a dot, matching `ALERT_KINDS`. Every schema requires `locale` (the short `de` or `en` through `LOCALE_CODE`, never the locale object), and an event a signed in person fires also requires `organizationId` while one that can precede an account declares none, so no call site invents a placeholder. Events carry ids and codes only: no email address, no contact name, no company name and no free text, enforced by the schema rather than the call site because `z.object` strips what it does not declare. Capture is fire and forget: a bad payload, an unconfigured PostHog and a transport failure all log and return `false`, never throwing into a server action's typed result or a task's retry, so a dropped event is the deliberate failure mode. Call `captureServerEvent` **after** the write that makes the work durable, and in a task pass a `dedupeKey` keyed on the run id (PostHog's event `uuid`), or a retried attempt that crashed mid run double counts one logical run. The nine server side events need no consent and are captured wherever the server can see them; `benchmark.viewed` is the one browser event and rides the consent gate in `src/lib/analytics/client.tsx`, so it undercounts by the rejection rate and is never compared directly against the server steps around it. A failed task reaches Slack through the `task.failed` alert from `tasks.onFailure` in `src/trigger/instrumentation.ts` (never `catchError`), best effort so it cannot mask the failure that caused it. Sentry tags every event with a release from the Vercel commit SHA, inlined by `next.config.ts` rather than read from `NEXT_PUBLIC_VERCEL_GIT_COMMIT_SHA`. The funnel is a saved PostHog insight per environment, and the per environment checklist (both PostHog keys including Trigger.dev, the Sentry build secrets, the Slack webhook, the funnel, consent, server events surviving rejection) lives in the runbook.
